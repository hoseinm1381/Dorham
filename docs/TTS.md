# Local Farsi and English voice-channel speech

Use `/tts your message`, or enable the TTS checkbox beside the composer. The ordinary text message is committed first, with the command removed. If its sender has no current voice membership, it remains a normal message. Otherwise speech is generated locally and delivered only to people who were in that same voice channel when it was sent and still have the same membership epoch. Being in another voice channel, viewing the same text chat, or knowing the audio URL does not grant access.

Speech uses local Piper 1.8.0 with the Persian amir medium and English LJSpeech medium voices. Mixed-script messages are split between the two voices. These models are not OS/browser voices and do not require an external speech service during use. The model cards are preserved under docs/licenses (Persian dataset CC0; English dataset public domain). Piper and the separate worker are GPL-3.0-or-later; the upstream license is preserved alongside the cards. Primary references: [Piper Python API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md), [Persian model](https://huggingface.co/rhasspy/piper-voices/blob/main/fa/fa_IR/amir/medium/MODEL_CARD), [English model](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/ljspeech/medium/MODEL_CARD).

## Provisioning

Run `sudo python3 deployment/install-tts.py` explicitly on the Linux host. It creates an isolated environment under /opt/dorham-tts, pins Python dependencies from tts-requirements.txt, verifies the model hashes and pinned source revision in tts-models.json, and does not change system Python. App startup never downloads a runtime or voice. DORHAM_TTS_PYTHON and DORHAM_TTS_MODELS can override the default interpreter and model directory. The service user needs read/execute access only. The separate speech worker runs with one ONNX thread at lower scheduling priority and retains the two models between requests.

The first request may take longer while models load. Speech is limited to 400 stored characters and one request per sender every four seconds; the server queues at most four jobs. Longer/rate-limited/unavailable requests remain normal chat messages with a sender notice. Synthesized audio is held only in a bounded in-memory cache for two minutes; it is authenticated, voice-epoch checked, private/no-store and never cached by the PWA. No message text is written to synthesis logs.

Moderator mute/speak permissions are enforced before and after synthesis. Leaving the channel before generation completes cancels delivery. Deafen/server-deafen prevents access; leaving/rejoining does not restore access to previous audio. The web player drops queued/playing speech when leaving, deafening or muting TTS. Speech uses the selected audio output and the sender's configured playback volume. Browser autoplay may require a user gesture. Native applications need a future rebuild to include playback.

Real Farsi, English and mixed synthesis are checked separately from browser delivery. Automated routing checks use generated PCM speech fixtures and test account membership; they do not certify pronunciation or physical speakers. No new media capacity certification is implied.
