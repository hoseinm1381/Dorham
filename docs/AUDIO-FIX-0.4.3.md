# Dorham 0.4.3 — audio controls

Volume and deafen now control the actual audio playback path. The SFU transport enables LiveKit's Web Audio mixer and uses participant volume for microphone and screen audio. SDK-owned muted audio elements keep its track lifecycle; the application no longer wraps those elements in a separate MediaElementAudioSource graph. The mesh fallback also feeds its gain from the received MediaStream and keeps its scheduling element silent. Both apply local deafen before awaiting microphone/control-plane acknowledgement, including for new subscriptions. Undeafening restores each participant's chosen level, including amplification up to 200%.

Settings and connection diagnostics expose independent noise suppression, echo cancellation and automatic microphone level switches. Preferences persist on the device. Supported changes apply during a call through track constraints without rejoining the room or opening a muted microphone. If a browser accepts constraints but reports the old settings, capture restarts with the new preferences while retaining mute. The SFU uses the SDK's locked constraint operation so capture preferences survive device switching and track restart. Browser support and effective settings are reported; browsers can ignore a preference or omit its effective setting. The built-in noise processor exposes boolean on/off, not an adjustable intensity. No extra DSP loop, third-party audio processing service or recurring stats poll was added.

“One-time administrator setup code” replaces “Single-use bootstrap secret” with an explanation: only the deployment operator has this code; it appoints the first global administrator once, and is separate from a password or invite. “Use role default” replaces “Inherit”: removing a channel-specific override uses the role permission rules again. Authorization and permission precedence are unchanged. English and Persian labels/help are included.

Copied PNG, JPEG, WebP and GIF images can be pasted into a channel or DM message box with Ctrl+V. The paste event supplies the image; the application never polls or reads the system clipboard independently. Images follow the existing compression preview, authenticated upload, quota and four-attachment rules. Sending remains explicit, captions are retained, and ordinary text paste is untouched. Guests, blocked DMs and message editing do not enable attachment paste. Test fixtures dispatch image-bearing clipboard events without reading or modifying the user's OS clipboard.

## Verification

The output regression uses two real browser clients, real backend/database, a deterministic microphone tone, and decoded WebRTC. It samples the graph at actual AudioContext destination edges after playback gain. It checks 0%, 50%, 100%, 200%, deafen silence, slider changes while deafened, a new subscription while deafened, and restoration after undeafening. Synthesized notification cues are disabled in this measurement. Inbound RTP energy and slider values alone are insufficient evidence of playback volume.

The same scenario runs through mesh and the operator's Iranian SFU using an isolated local application database and unique room. SFU fixture rooms are removed after testing. Processing checks use Chromium's actual fake microphone capture and inspect effective track settings, capture restart when required, device switching, persistence and mute preservation. Unit tests cover immediate deafen despite delayed acknowledgements and failed processing changes retaining the previous preference.

Physical speaker/headset output, acoustic noise/echo quality, elevated games, Android and domestic-only outage behavior remain untested. The earlier ten-user/four-share capacity failure is a separate unresolved gate. This release does not establish that capacity. Android remains deferred by request. Existing runtime dependencies, schema, media-network setup and upload quotas are unchanged.

Primary references: [LiveKit participant volume](https://docs.livekit.io/reference/client-sdk-js/classes/RemoteParticipant.html#setVolume), [browser noise suppression](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/noiseSuppression), [capture constraints and effective settings](https://developer.mozilla.org/en-US/docs/Web/API/Media_Capture_and_Streams_API/Constraints). The pinned SDK implementation was also inspected locally.

Accepted release checks: lint, types, 66 unit/API tests, API/web/desktop production builds; mesh and Iranian-SFU output gain/deafen scenarios; live microphone processing in both transports; clipboard images in channels and DMs; image compression, recovery administration and custom-role/profile browser regressions; and the installed unsigned Windows application including clipboard paste, processing while muted, background push/toggle keys, protected credentials and lifecycle. SFU measured RMS was 0.0559 at 100%, 0.0279 at 50%, and 0.1121 at 200%; zero volume and deafen reached the test's silence threshold below 0.000001. Acoustic/headset performance is not inferred from these synthetic measurements. Early failed attempts are retained in local logs; they exposed Chromium's unchanged processing and a test retaining its explicit microphone lock before a hotkey test. Both were addressed before the accepted runs.

Live deployment preserved all 35 database tables (6 accounts, 1 server, 16 messages at deployment), schema 3, and existing configuration. Public production assets are compared by hash. Rollback retains the preceding application and a coordinated private data/config backup; private backups and credentials are excluded from release ZIPs. No production test account was created.
