# Dorham 0.4.2 — Persian readability and chat connection ping

Persian now uses a locally bundled Vazirmatn variable font with proper line spacing and unspaced Arabic letter shaping. English remains selectable. All literal translation keys in the current web interface have Persian entries, including voice-input and background-hotkey settings. A test checks translation coverage and placeholder parity. The font is precached with the public PWA shell and works offline without an external font CDN; see [font provenance and license](THIRD-PARTY-FONTS.md).

The Persian copy also replaces obscure or literal wording with familiar interface terms: مگابایت / گیگابایت, موقتاً غیرفعال for idle, عکس پروفایل, clear microphone/listening controls, management activation and login-expiry messages. Upload limits and storage calculations remain unchanged in bytes (binary MiB/GiB as in the English interface); Persian file sizes use familiar labels and localized digits. Compression shows labelled original/compressed sizes instead of a direction-sensitive arrow. The online count no longer repeats نفر. Permission wording retains explicit deny precedence and distinguishes server ownership from global administration.

This release revises 105 existing Persian entries and adds 33. The installed Windows build also passes actual bundled-font loading after switching to Persian, measured chat ping display, protected credentials/sandbox/tray checks, inline media and background talk-key safety. The hotkey test holds each synthetic key state for 80 ms so the 20 ms native sampler can observe both edges; the earlier sub-poll release/repress failure log is retained. Physical keyboard/protected-game testing remains open. Expansion scenarios pass across the initial run and the corrected version-label retry; core authentication/chat/PTT checks pass.

Messages choose their paragraph direction from their contents, independently of the interface language. Links and mixed-language display names use directional isolation. Half-spaces, Arabic/Persian letter choices and original message contents remain unchanged in storage. People search matches Arabic keyboard variants of Persian letters, diacritics, half-spaces and Persian/Arabic digits. Enter during IME composition commits text without sending prematurely. The mobile Persian server rail and channel drawer both open from the right.

Online users have a compact ping badge beside message author names, in server member lists, People and profiles; the header also shows your connection ping. Persian mode uses Persian digits and milliseconds. The server measures a Socket.IO acknowledgement round trip using a monotonic clock: it is **chat-server RTT**, including transport/browser scheduling, not peer-to-peer distance or voice/SFU latency. If several connections belong to one account, the fastest fresh connection is shown. Colours supplement the numeric value: below 150 ms green, 150–299 ms amber, 300 ms or more pink. These are display bands, not a voice-quality guarantee.

The server samples at connection and every 15 seconds, allowing 5 seconds for a response and 45 seconds freshness. Timeouts, malformed replies and old clients that do not implement the probe show “Ping unavailable”; offline users have no badge. Disconnects remove samples. Timed rounds do not overlap. Only the existing authenticated presence audience receives these measurements; no IP addresses, client-supplied timing values or permanent history are exposed. There are no new database writes, schema changes, WebRTC-stat loops, services or dependencies.

Verification: lint, types, 63 unit/API tests and API/web/desktop builds pass. New integration tests use actual authenticated Socket.IO clients, check measured delayed replies, malformed acknowledgements, duplicate connections, expiration and disconnect cleanup. Three browser scenarios cover Persian desktop/mobile layout, real loaded font, offline shell/font, mixed-language messages/links, keyboard-variant search, IME Enter, translated hotkeys, actual ping display/removal, and real upload metadata showing Persian file-size labels and digits. A geometry assertion verifies actual glyph alignment, catching a compatibility minifier's language-based rewrite of `:dir()`; message layout now uses native `dir=auto` paragraphs without that selector. Initial test-fixture errors and a navigation-animation timing assertion were corrected; failed logs remain under `artifacts/logs/persian-ping-*`. Screenshots are in `artifacts/evidence/persian-*`. The normal 4 GiB browser guard applies. No heavy media stress test or Android build is part of this update; the [previous ten-user/four-share failure](OPTIMIZATION-0.4.1.md) remains unresolved.

Build with `npm run verify`; run the focused UI scenarios with `node scripts/browser-tests.mjs --persian`. Windows packaging uses `npm run package:windows`. Release artifacts are `artifacts/Dorham-0.4.2-{Source,Server}.zip` and `artifacts/v0.4.2/windows/Dorham-0.4.2-Windows-x64.exe` (unsigned). Existing accounts/history and media configuration are preserved. Refresh the website or install the new Windows build so the client responds to the ping probe. Physical-device and Iran-only outage testing remain open.
