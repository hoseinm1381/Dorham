# Dorham 0.7.6 — domain, signed-in recovery and private voice tests

The primary website is **https://dorhamapp.ir/**. New Windows installations use this address by default. Existing saved server addresses remain available, and the previous nip.io endpoint still works against the same accounts and messages. A browser visiting the new origin needs to sign in there once; sessions and device preferences are not copied between website origins.

Registered users can choose **Reset password while signed in** in Profile settings, Privacy → Account recovery, or the one-time recovery reminder. Only a new password is needed. The API requires an authenticated, unexpired session and the existing browser CSRF protections; it rejects guests and signed-out or revoked sessions. Saving retains the current session, signs out other devices and records an audit event without the password. Existing recovery codes stay valid until explicitly regenerated. Signed-out recovery still needs an unused recovery code or an administrator-issued temporary password. The password-reset guide explains both paths. The deployment does not change any existing password or the server's SSH password.

The + Direct messages picker marks people with real message history as **Already chatted**. Empty composers do not count. The badge updates from the same live conversation activity used to order the DM list, and a new person remains discoverable through +.

Microphone and speaker tests temporarily mute and deafen the live voice connection. Recording and playback each acquire their own isolation period, and the previous chosen mute/deafen settings return when that activity ends. Closing the panel, cancelling microphone permission, capture errors and overlapping tests release their own isolation. Talk hotkeys cannot bypass it. Tests use separate local capture, never send their recordings to the server, and do not replace or stop the call's microphone track.

Opt-in boost now extends to **+45 dB**, approximately **178 times signal amplitude**. The normal 50–250% range remains the default, and unchecking boost immediately caps gain at 250%. The warning explains loud noise and distortion. Above +20 dB, an optional local soft noise gate reduces background noise between speech. Its threshold is adjustable from −90 to −40 dB, default −70 dB; lower it if a very quiet voice is cut off. It runs in the existing Web Audio graph and is fully bypassed at lower gains or when disabled. It is an envelope-controlled expander, not an AI denoiser, and cannot separate noise mixed with speech. Private playback uses the same filter settings. No model, worklet download, server DSP or new runtime dependency is added. The browser's existing noise-suppression control remains available independently.

## Verification

Lint, TypeScript, all **147 unit/API tests in 26 files**, production builds and the standalone compiled-runtime smoke check pass. Eight Chrome scenarios cover the DM indicator, registration and legacy recovery, resetting a forgotten password while signed in, invitations, sharing setup, icons and real audio processing. The authenticated reset test verifies other-device revocation, current-session retention, invalid password rejection, retry deduplication, recovery-code preservation and audit privacy.

Two-client direct voice tests measure approximately **179.35×** decoded amplitude at +45 dB and 31.79× at +30 dB from a quiet synthetic source. Mute silence and restoration to the normal range pass. Separate live-call tests verify silence in both directions during recording, local-only playback, panel-close restoration and preservation of a previously muted/deafened state. The actual Web Audio noise-filter test measures 0.01× amplitude for a low-level background tone (about −40 dB), unchanged amplitude for the stronger test voice and preservation of a quiet voice with a lower threshold. These are signal tests, not subjective or physical-microphone acceptance.

The unsigned Windows installer is installed in an isolated test folder. All 40 web files and four desktop-shell files match the build. Schema 9 is unchanged. The independently downloaded pre-release backup verifies all 38 table digests, five file digests, SQLite integrity and foreign keys. Deployment preserves 35 persistent table digests, all four avatar/attachment files and the domain configuration. The previous application and private backup are retained. Evidence uses `v076-` in `artifacts/evidence` and `artifacts/logs`.

Public Chrome and the installed Windows app pass bidirectional decoded voice and screen sharing over HTTPS/WSS and forced TURN/TLS through the new domain, using ordinary public DNS without pins. At +45 dB, measured decoded ratios are approximately 172.08× Chrome-to-Windows and 178.17× Windows-to-Chrome. The test verifies automatic test deafen, private playback, mute cues, recipient volume, outgoing 50–250% gain, invitations, revisioned permissions, all nine browser sharing caps, three Windows caps and live FPS changes without recapture. Peak browser RAM is 1607.6 MiB under the 4096 MiB guard. Earlier attempts stopped at that guard before the user closed unused tabs; their manifest-owned fixtures were removed. ## Domain operations

Apex, www, voice and turn are DNS-only records pointing to the Iranian VPS. Their trusted TLS certificate expires on 2027-01-29. The existing renewal timer is retained; its deployment hook now refreshes both certificate bundles and validates HAProxy before reloading it. Caddy handles both voice names with the existing admission gate and token redaction. HAProxy preserves the previous TURN hostname while adding `turn.dorhamapp.ir`. API public links use the new origin and allowed origins retain existing clients. LiveKit advertises the new voice/TURN path. HTTP redirects to HTTPS, private paths remain denied, and normal public DNS/TLS checks pass for all four names.

Activation retained a fresh private data/configuration backup and an automatic configuration rollback path. Four services remain healthy. DNS from the Iranian VPS and ordinary public connectivity are verified; a real national Internet outage and renewal during an extended outage are not verified. See [domain operations](DOMAIN.md).
