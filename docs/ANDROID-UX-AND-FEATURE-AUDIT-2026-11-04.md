# Android UX, features and performance audit — 4 November 2026

Android needs a mobile interaction design and a completed native-media integration. Rebuilding the current web UI into an APK alone will preserve the main problems.

This is an analysis, not an implementation or publication. Android remains the published 1.1.0 release; web/Windows are 1.1.1. No production accounts, services, installers or phone installations were changed by this audit.

## Evidence and limits

- Reviewed the current React/Capacitor/Kotlin media, foreground service, routing, downloads, updater, permissions and release/test code.
- Inspected the retained released Android 1.1.0 APK: 70,000,075 bytes, SHA-256 `ab081ff74ee1dd636c5e450013ab33173f3dadf742edaca44a791138247f323f`. This agrees with the earlier independent release-verification record.
- Extracted its actual packaged web assets into an isolated audit root. Ran them in headless touch/mobile Chrome at 390 × 844 against a temporary loopback Go backend. A simulated Capacitor bridge recorded calls and delivered native events. This verifies shipped JavaScript/layout behavior, **not** Android capture, Bluetooth, background survival or decoded native audio/video.
- Reproduced hidden participants/call controls, ineffective members toggle, native capture request routing, and missing native incoming-video display. The final probe passed with no page errors. The first probe sampled the navigation animation too early; it was corrected to wait for navigation closure/transition before measuring.
- No ADB device is connected. The user clarified that on **Poco F3 / Android 13**, screen sharing requests permission and **does work**, following the entire phone screen across apps. That is expected whole-display capture on Android 13, not a confirmed outgoing-capture defect. Android's built-in single-app sharing is available from Android 14. This is user-reported acceptance, not a new agent-controlled decoded-media test. Earlier release compilation/signature/ZIP alignment results and earlier Poco F3 acceptance do not substitute for new physical Android tests.
- Evidence: `artifacts/android-audit-2026-11-04/apk-ui-audit.json`; screenshots `apk-voice-mobile.png`, `apk-navigation-mobile.png`, `apk-share-mobile.png`, `apk-native-viewer-disconnected.png`. Probe: `.tools/android-audit-ui.mjs`. Browser process memory remained below the existing 3500 MiB stop threshold.

## Four implementation priorities

1. **Usable mobile channels and calls.** Participants before/after joining, functional member sheet, persistent call bar, clear text/voice navigation, touch actions, keyboard/Back/RTL/accessibility. Mostly shared frontend; existing voice directory should suffice.
2. **Complete screen sharing and viewing.** Connect native viewer, clarify whole-phone capture on Android 13 and offer OS-supported app selection on newer devices, add supported phone playback audio, separate stream audio, cancellation/system stop/rotation/retry. Primarily Kotlin plus TypeScript bridge/UI; verify existing backend audio lease/source contracts and extend narrowly only if needed. The user has confirmed outgoing capture works on Poco F3 / Android 13.
3. **Reliable phone audio and background behavior.** Accurate route controls, honest processing features, speaker events/reconnect state, touch talk mode, background TTS/call testing and useful notifications. Push delivery/app links add backend and deployment work; basic mobile controls do not need a backend rewrite.
4. **Smoothness, battery, updates and release quality.** Port shared 1.1.1 performance/TTS UI, reduce telemetry/render/subscription work, evaluate APK splits, improve updater/download feedback, replace native test scaffolds. Measure before claiming gains.

Keep the current React/Capacitor approach initially: the observed failures are addressable integration and interaction defects, and do not by themselves justify an expensive full rewrite.

## Required acceptance gates for a future release

- Physical phone: install over 1.1.0 with the permanent certificate, retain login/preferences; English/Persian, RTL and text scaling.
- Browse channels without joining; see correct occupants/count and live join/leave/mute/deafen/speaking; member button always opens a usable sheet; call controls stay visible while navigating/chatting.
- Android sends to independent Windows and web receivers, and watches each sender; actual moving decoded frames, no simulated bridge. Test both supported production media mode and compatibility mode where retained.
- MediaProjection accept/cancel, repeat start/stop, system stop, app-only/full-display where supported, rotation, permission denial/regrant, capture failure/retry and no stale lease or microphone leak.
- Eligible game/media playback sound plus microphone, independent stream volume/mute, deafen, own-call audio exclusion; truthful message when content cannot be captured.
- Speaker/wired/USB/Bluetooth output and microphone route, connect/disconnect mid-call, incoming phone call, media focus, no duplicate SDK/app ownership.
- Lock/background for a sustained call, return-to-app, Wi-Fi↔mobile switch, brief network loss, service/process death; no false connected status or stale member.
- TTS full-message playback/progress on phone, headset/speaker routing, background/lock behavior and private membership rules.
- Controlled updater from installed old release to new signed APK, download progress/interruption/retry, unknown-source permission and Android installer confirmation, login retained; installation protected during calls.
- Before/after measurements on the user's phone: startup, typing/scroll responsiveness, long chat DOM, memory, call CPU, battery/thermal trend and cellular data. Do not infer these from desktop Chrome.

## Android platform constraints checked

Implementation follow-up: Android 1.1.1 was published after preliminary Poco F3 / Android 13 acceptance. See [features, verification and remaining physical/external requirements](RELEASE-1.1.1-ANDROID.md). This audit remains the historical baseline; publication does not imply that all 28 findings or Firebase delivery are resolved.

- [Media projection](https://developer.android.com/media/grow/media-projection): Android requires screen-capture consent; Android 14+ has single-use projection/session constraints and foreground-service requirements. These are constraints to respect, not reasons to drop phone sharing.
- [Capture video and audio playback](https://developer.android.com/media/platform/av-capture): playback capture is available from Android 10, but requires permission/consent, same profile, permitted player usage and capture policy. Some apps/content cannot be captured; do not promise every phone sound. Excluding Dorham's UID is a supported filtering option.
- [Manage audio focus](https://developer.android.com/media/optimize/audio-focus): focus/interruption ownership must be tested, including newer foreground/focus requirements. No fresh physical focus result is claimed here.
