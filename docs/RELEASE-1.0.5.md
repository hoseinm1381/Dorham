# Dorham 1.0.5 — web and Windows

Mute and unmute feedback uses twice the previous signal amplitude (+6.02 dB). The full tone envelope is scaled; note order/duration and other notification levels are unchanged. These cues remain local and respect the existing voice-sound preference. This does not promise twice the perceived loudness on every speaker.

Windows adds an off-by-default voice overlay under Settings → Audio. It displays the connected channel and current participants, speaking, muted, server-muted and deafened states. It uses a transparent native window on the primary display, with four corner positions. It stays above normal windows, does not take focus and passes mouse clicks to the underlying game. It hides when leaving voice, disabling it, locking Windows or when the main renderer exits/reloads. Names are rendered as text in a separate sandboxed, isolated, network-free renderer with no session/credential bridge.

This is the operator-approved native borderless overlay, not an injected graphics hook. It supports windowed/borderless applications. Exclusive-fullscreen games are not supported; no claim is made for a particular game's behavior until tested.

Android remains the existing signed 1.0.4 binary and build number. No Android rebuild is included. Backend runtime and data schema also remain 1.0.4. New web/Windows clients use independently validated platform release metadata. Legacy latest.json stays unchanged for Android and old web menus. A narrow legacy Electron main-process route supplies the Windows update manifest; new Windows apps use windows.json directly. The public menu lists Windows 1.0.5 and Android 1.0.4.

Verification: lint/types/builds, 174 unit/API tests in 35 files, two-client mute-cue/talk-key/privacy checks and download-menu regressions pass. Chrome offline rendering gives exact RMS ratios of 2 for mute/unmute and 1 for all other cues against 1.0.4. A packaged Windows test verifies actual voice membership/mute status, settings/persistence, sandboxing, leave/lock lifecycle and native WS_EX_TRANSPARENT/NOACTIVATE/TOPMOST flags. A real OS mouse click passes through the overlay into a temporary borderless test window without changing focus. This test is separate from acceptance inside a commercial game.

Web and Windows 1.0.5 are deployed after a fresh independently verified rollback backup (38 tables, 14 stored files and 195 prior web files). The web rollout verifies 124 current files, retains previous hashed assets and preserves SQLite integrity/foreign keys. The real Windows 1.0.4-to-1.0.5 upgrade retains the install directory/GUID and one uninstall entry; all 124 web files and 11 shell/overlay files match the ASAR. It updates web assets and immutable Windows downloads while retaining previous assets/installers, the Android manifest/binary, user data and service processes. The Caddy download-metadata change is validated and reloaded; voice services are not restarted. Windows remains unsigned and retains the existing app ID/NSIS identity.

Public verification passes every web file and every Windows installer byte over HTTPS. The live public menu lists Windows 1.0.5 and Android 1.0.4; actual Windows 1.0.4 sees Update 1.0.5, installed 1.0.5 sees no equal-version update, and the legacy renderer menu remains usable. Android’s original manifest and signed binary are unchanged. No commercial-game acceptance is claimed before the operator tests it.
