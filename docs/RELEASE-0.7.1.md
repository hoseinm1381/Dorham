# Dorham 0.7.1 - microphone gain recovery and local voice test

The microphone-gain control now checks that its SFU gain processor is still attached, even if the microphone's mute/enabled state has not changed. A missing processor is recreated with the latest selected gain and mute state. This closes a lifecycle gap after SDK audio-graph removal; it is not a confirmed diagnosis of the reported physical-microphone case. Gain controls share live updates, and the interface shows signal gain in dB as well as percent.

Account settings > Audio > Hear your microphone records up to five seconds using the chosen microphone and capture-processing settings. Users then play the recording through their selected output and change gain while listening. A meter flags predicted/actual clipping. The recording remains in memory, is never uploaded, and is cleared when the panel closes or its devices change. Capture stops before playback; permission cancellation and late capture results release their tracks. Playback can be stopped. The same local test is available in voice connection settings. Existing voice-call mute and publication state are unaffected.

The 50-250% range retains its linear amplitude meaning. 250% is approximately +8 dB, not 2.5 times perceived loudness. Loud input can already be near full scale and clip when boosted. No additional compression or undocumented percentage remapping is introduced.

Before this change, native Chrome getUserMedia capture with an original generated-speech WAV measured remote RMS of 0.1641 at 100% and 0.3785 at 250% over direct WebRTC (2.31x). The hosted SFU path measured 0.1663 and 0.3604 (2.17x), with automatic gain, echo cancellation and noise suppression active. Loud peaks reached full scale. These measurements exercised the browser capture path without substituting a Web Audio input stream; they still use a generated speech fixture rather than the user's physical microphone, speakers or listening environment. The reported separate-device result was not reproduced or dismissed by these tests.

Lint, TypeScript, all 128 unit/API tests and production API/web/desktop builds pass. The gain-processor regression verifies recovery while unmuted and muted. The browser self-test measures 2.52x local playback at 250%, detects clipping, stops capture after five seconds, releases late permission results, erases recordings on close and makes no audio upload. Desktop/mobile screenshots were inspected. The SFU gain regression checks 50/100/150/250%, saved gain, local playback while muted, device replacement, deafen, rejoin, reload and reset. An initial self-test attempt used the previous compiled web UI and timed out; the completed 0.7.1 build passes. A unit-test mock needed its track stop method before its cleanup could pass.

Public Chrome/installed-Windows tests through HTTPS/WSS and forced TURN/TLS pass gain in both directions, local recording/playback while muted without sending it, per-person volume, mute cues, screen sharing, deafen, permissions and invites. Received RMS at 50/100/250% is 0.02834/0.05596/0.14048 from Windows, and 0.02849/0.05659/0.14208 from Chrome with a quiet synthetic source. The shared 4 GiB guard remains unchanged; the public run peaked at 2,296.5 MiB combined browser memory. All 39 installed web files and four shell files match the final build. Normal-DNS certificate-validated HTTPS returns the exact released HTML.

The independently downloaded backup verifies 38 tables and four data files. Deployment preserves all 35 persistent table digests, all three avatar/attachment files and exact configuration, with all four services active. The previous application remains at `/opt/dorham-before-0.7.1`. Only the two manifest-owned test accounts, test server and media room were removed; ten accounts, three servers and 32 messages remain after cleanup. The private test tunnel is closed and its ephemeral credential file removed.

Evidence and package hashes are recorded under `artifacts/evidence/v071-*`, `microphone-*` and `artifacts/v0.7.1`. The recording engine loads on demand and is excluded from eager PWA caching. Dependencies and schema 8 are unchanged; no fresh dependency advisory audit is claimed. Windows remains unsigned; Android, physical acoustic certification and earlier large-call capacity limits remain deferred.
